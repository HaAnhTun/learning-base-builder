The tool system is the full set of built-in capabilities it can invoke. Read, write, and edit handle files.

**[00:40]** Bash executes shell commands. Glob and grep find files and text. Web search and web fetch reach the web. Agent delegates a subtask to a subagent, with its own separate context window. Two of these earn a closer look later in this lesson. Edit makes targeted find and replace changes, while write replaces a whole file, and agent is what turns Claude Code from a single worker into an orchestrator.

**[01:07]** We'll come back to both. Read is the safest tool in the set. It views the contents of a file without making any modifications. One clarification worth locking in. Read operates on files, not directories. If Claude needs a directory listing, it uses bash with a command like ls.

**[01:26]** If it needs to find files by name or by content, it uses glob or grep. Read itself returns a file's contents, including rendered images, PDFs, and notebooks. Claude typically runs read before edit to confirm the current state of a file before changing it. That read before edit pattern prevents a common class of errors, where Claude acts on stale assumptions about what a file contains. It has no modification risk by design, so reading the relevant files before modifying them is standard practice. Write and edit are both file modification tools, but they behave very differently.

**[02:06]** Write overwrites the entire file. Every byte of existing content is replaced with the new content. If you use write on an existing file and leave out 10 lines, those 10 lines are gone. There's no partial update. Edit works differently. It takes a target string and a replacement string and performs a scoped find and replace on the file.

**[02:27]** Only the matched section changes. Everything else stays intact. For most code changes, edit is the right tool. Use write for creating new files, or for intentional full rewrites where you want to replace everything. Conflating them is an exam trap worth knowing. Bash is the most capable tool and the most dangerous one.

**[02:44]** It executes any shell command. Running scripts, installing packages, moving or deleting files, starting processes, querying databases, calling APIs. There's no built-in constraint on what it can affect. A poorly scoped bash command can delete files, corrupt state, or make irreversible changes to the system with no undo path. The permission model and hooks are the primary controls. Without them, bash has wide reach across the system.

**[03:19]** Understanding this is essential for designing Claude code workflows that run in automated or production environments where a bad bash call could cause serious damage. Web Search lets Claude query the web for information that goes beyond what it knows from training. Current documentation, recent API changes, error messages from new library versions, release notes. These are all things that Web Search can retrieve that Claude's training data might not cover. Results come back as text that Claude reads and reasons about before acting. Claude selects Web Search when it determines that the task requires information it can't reliably know from training.

**[04:00]** It's not always invoked, only when the current task has a knowledge gap that a web query can fill. Web Search extends Claude code from a local codebase tool to one that can pull in current external information. The agent tool spawns a sub-agent with its own separate context window. The parent session delegates a sub-task to the sub-agent, which runs independently and returns a result. The main use cases are tasks too large to fit in the current session's context window, and tasks that are isolated enough to run in parallel with other work. Agent is the tool that turns Claude code into a multi-agent orchestrator, the parent coordinates.

**[04:43]** The sub-agents do the isolated work. Because each sub-agent has its own context window, you can handle much larger tasks by decomposing them into parallel sub-tasks and delegating each one to a separate agent. Tool selection in Claude code is task-driven. Claude doesn't pick tools based on capability alone. It picks the tool that matches what the current step requires. Inspecting existing state, before acting, read.

**[05:13]** Changing specific lines in a known file, edit. Creating a new file or completely rewriting one, write. Running a command, script, or system operation, bash. Looking up current information that training data won't have, web search. Delegating an isolated sub-task to its own context, agent. The planning loop runs this selection decision at every step.

**[05:37]** Getting tool selection right is what makes a multi-step workflow execute coherently, rather than reaching for the wrong capability at the wrong time. Every tool in the set does one narrow job, and Claude repicks between them at each step of the task. That's why a request phrased slightly differently can take a completely different route through your files. One thing to watch. Bash is the exception to that narrowness. It'll run whatever you hand it, so scope it before you loosen anything else.
